# graphql-authz-mutations.txt
#
# Mutation names to probe when a GraphQL schema hides its privileged operations
# from introspection, or when introspection is disabled entirely.
#
# Why this list exists: on a real target I burned a session guessing at
# admin-flavoured mutations one at a time (adminDeleteAddress, forceDeleteAddress,
# ...) — all absent. The useful signal was not any single name, it was that the
# error message distinguishes "field doesn't exist" from "field exists, wrong
# arguments". Enumerate the whole list, then read the error taxonomy:
#
#   "Cannot query field 'x' on type 'Mutation'"  -> does not exist
#   "Unknown argument 'y' on field 'x'"          -> EXISTS, keep going
#   "Field 'x' argument 'y' of type 'ID!' is required" -> EXISTS, signature leaked
#
# That second and third response are how you map a schema you can't introspect.
# Write-up: https://github.com/pablodlz/writeups/blob/main/web/graphql-phantom-success.md
#
# Substitute the target's own object nouns for <Object> — Address, PaymentMethod,
# Shipment, Invoice, ApiKey, Member, Team, Webhook, Integration.
