# auth-bypass-headers.txt
#
# HTTP request headers that some backends trust as an identity or privilege
# assertion when they are set by an upstream proxy — and that are worth trying
# when a resolver or endpoint enforces authorisation somewhere you can't see.
#
# Provenance: every entry below was actually sent against a live target during
# an authorisation investigation on a Relay/GraphQL API (write-up:
# https://github.com/pablodlz/writeups/blob/main/web/graphql-phantom-success.md).
# None of them worked there. That is the point of publishing the list: the next
# person enumerates the whole set in one pass instead of rediscovering it over
# four sessions.
#
# Usage: pair with a value that names another principal (a victim user id, or a
# boolean for the admin flags) and compare the response against the same request
# with the header absent. Set one at a time first, then in combination — some
# gateways only honour a header when a companion header is also present.
#
# Not a substitute for a real bypass hypothesis. If the check is in the database
# WHERE clause, none of these will ever fire, and you should be measuring state
# instead. See the write-up.
